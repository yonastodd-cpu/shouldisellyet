# Case-study panel — what was served, what is displayed, what remains

Prompt A, 2026-08-19.

## What was happening

`web/data/cases/` held four historical market files and their charts, all
committed and all inside the deployed artifact. Every homepage visitor's
browser downloaded one of the JSON files in full. Each carries:

- a `series` of 48–54 monthly records, each holding that month's vendor
  measurements (`mos`, `spy`, `pd`, `dom`, `domy`)
- `peak_price` and `trough_price` — raw vendor median prices
  (Austin: 596,022 and 443,582)

The panel displayed **four fields**: market name, the month our dials first
crossed, how many months later prices fell, and the peak-to-trough percentage.

## The finding that made this cheap

Those four fields were **already in `index.json`**, the small file the
homepage fetches first to decide which case to show. The second request — the
one that pulled 48–54 months of vendor measurements into the browser — was
fetching data the panel never used. No figure had to be recomputed and no new
precomputed file was needed: `index.json` already is one.

Verified: the panel reads `first_signal`, `lead_months`, `name`,
`peak_to_trough`; `index.json` provides all four, and contains no `series`,
no `peak_price`, no `trough_price`, and no monthly measurement of any kind.

## Is any displayed figure a raw vendor measurement?

**No.** All four are ours:

| Displayed | Origin |
|---|---|
| Market name | place name |
| First signal month | when *our* dials crossed |
| Lead months | our calculation |
| Peak-to-trough % | our calculation over a vendor price series |

The last is derived in the same sense as the published research aggregates: a
percentage computed from vendor data, not a vendor figure reproduced. Nothing
was inlined that needed a product decision.

## What moved

`pipeline/cases/` — outside `web/`, so outside the deployed artifact:
`austin-2021`, `boise-2021`, `cape-coral-2022`, `miss-39500`, each `.json`
and `.png`. Still in the repository pending the purge; still readable by the
build.

`web/data/cases/index.json` stays public. Derived indicators only.

## Why they were not moved to `_private_data_export/` yet

`/stories/boise/` is generated at deploy from a case file and is gitignored,
so a build that cannot read one **deletes a live URL** — the founding rule of
this migration. The same applies to the research track record. Moving the
files outside `web/` stops public serving today with no URL loss; moving them
outside the repo needs the CI provisioning path that original Prompt 1 builds.

## Side effects, deliberate

- **Research charts withdrawn.** `copy_case_charts()` was copying the four
  PNGs into each published research release, and the release page embedded
  them. Each plots a vendor's monthly measurements. The copy and the `<img>`
  are gone; the derived figures beside them still render.
- **Marketing copy repointed.** `marketing_tasks.py` told the operator to
  attach `web/data/cases/{id}.png` to a post. It now names the private path
  and says the chart must not be attached publicly without clearance.
